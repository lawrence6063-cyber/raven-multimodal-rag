2 · 关键发现：dense embedding 空间错位（发现 → 诊断 → 修复）

问题现象：消融初跑时，纯 dense 检索（no_fusion）nDCG@10 仅 0.023，且对任意查询都返回同一批 08_swe_bench.pdf 的 chunk——dense 检索形同报废。

三步诊断

诊断步骤结果判定
① query embedding 是否有区分度cos(不同语义文本)=0.70 / 0.58正常 ✓
② 库内存储向量是否有区分度两两 cos 分布 0.15~0.81正常 ✓
③ 库内 chunk 原文重新编码 vs 其存储向量cos ≈ 0.16（应 ≈1.0）空间错位 ✗

根因：建库时使用的 embedding 与当前 query 时的 embedding 不在同一向量空间。

修复：确认 embedding 确定性（cos=1.0000）后，复用 Chroma 已存的 chunk 原文，用当前 embedding 重嵌 8321 条文本向量（60 分钟，0 失败，不重新解析 PDF）。修复后 dense-only nDCG@10 从 0.023 → 0.694。

7 · 多跳专项：single-shot vs Agentic RAG（Recall Completeness）

Caveat（口径边界）：前四节 golden 集偏单跳事实型查询，对 agentic 的多跳/分解能力不利。 为公平评估 agentic 的完整度收益，本节另构造 8 条真·跨域多跳 query（每条预期 3~5 篇论文）做专项对比。

做配对单变量对比：对照组 = 一次 hybrid+CE 检索；实验组 = 完整 AgenticRAG （route → 改写/分解 → 多跳 → 反思回灌 → 合成）。两 arm 共用同一检索器/精排器，并把最终上下文预算对齐为 top_k=20，唯一变量是 agentic 编排。指标 = source 级 Recall Completeness（预期论文覆盖率）+ Hit Rate。 脚本 scripts/eval_multihop_singleshot_vs_agentic.py，结果 experiments/results/multihop_singleshot_vs_agentic.json。

ΔRecall Completeness = −0.019，配对 bootstrap 95% CI [−0.194, +0.150]（跨 0）， 符号检验 win 2 / tie 4 / loss 2 —— 多跳完整度上无显著增益； ΔHit Rate = +12.5%（87.5%→100%）：agentic 靠子问题分解救回 single-shot 完全命中失败的 1 条 query （Recall 0.0→0.4），但在 single-shot 已完整覆盖的 2 条上出现回退（1.0→0.75、1.0→0.5），因多跳累积 + 全局分数排序 + top-k 截断把 off-topic 高分 chunk 挤入、稀释了已覆盖的 source。

关键结论修正：早期"Agentic 把 Recall Completeness 从 0.287 提升到 0.410"的数据来自 向量库重嵌之前——彼时 embedding 空间错位、dense-only nDCG≈0.02，single-shot 几乎全靠 BM25 故完整度很差， agentic 的查询分解能弥补。重嵌修复 dense 后 single-shot 本身已强（0.573），该完整度红利消失。 因此 Agentic 的价值应重新定位为召回鲁棒性兜底（把难 query 的 Hit Rate 兜到 100%）与复杂推理路径， 而非"多跳完整度显著提升"；代价是延迟约 24 倍（3s→73s）。

8 · 组合式证据链专项：有利方向是“按需分解”，不是盲目反思

找到稳定正收益方向：对必须同时覆盖两篇论文证据的 composition query， Agentic RAG 中的查询分解 + 多子查询检索显著优于 single-shot；继续叠加 route / reflect / 多跳回灌反而退化。 因此工程方向应是 complexity-gated selective agentic：复杂组合题启用分解，只有证据不足时才触发反思。

数据先于正式实验冻结：从既有 chunk-level golden 证据按固定种子构造 30 条双证据题（6 dev + 24 test）， 每题记录两个精确 chunk、source 与文本 SHA-256；正式统计只使用 24 条 test。 三 arm 共用 tongyi embedding、hybrid+CE、DeepSeek 合成、retrieval_top_k=20 和最终 20 chunk 预算。 数据 data/agentic_bridge_qa.json，SHA-256 770cc4f49eab7683b0ea5e076963b99150b90b968acbaa8371fb1f0eff3946cd； 脚本 scripts/eval_agentic_bridge_qa.py，结果 experiments/results/agentic_bridge_qa.json。

9 · 结论与工程建议

  • Dense 是检索主力：贡献 nDCG@10 +0.262（p<0.001）。前提是 embedding 空间对齐——本实验最大教训。
  • cross-encoder 精排显著且高性价比：+0.154 nDCG@10，本地毫秒级，全面优于 LLM rerank。
  • BM25 稀疏融合在此语料收益不显著（p=0.86）：当前 dense 已足够强，RRF 更适合作为鲁棒性冗余。
  • Agentic RAG 的有效边界已定位：单跳默认走快速 hybrid+CE；组合式双证据题启用 decompose-only，可把证据链完整率从 29.2% 提至 58.3%（CI 不跨 0）；当前 full-agentic 反思链质量更低且 p95 达 111.6s，暂不应默认开启。
  • 推荐生产策略：增加 query complexity gate，单跳→single-shot，显式组合/比较题→decompose-only，只有可观测到证据缺口且有剩余预算时→reflect，并设置延迟与调用硬上限。
